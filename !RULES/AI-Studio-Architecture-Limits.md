# BTStudio — Архітектура AI Studio та межі можливостей розширення

> Цей документ описує технічну архітектуру Google AI Studio, задокументовані обмеження та чому певні функції принципово неможливо реалізувати через browser extension.

---

## 1. Як влаштований AI Studio (технічна архітектура)

### SPA на Angular 17+ з CDK Virtual Scroll
AI Studio — це Single Page Application на Angular з `cdk-virtual-scroll-viewport`.

**Що це означає на практиці:**
- Рендеряться тільки ті `ms-chat-turn`, які зараз **видно на екрані** (±2 буфер).
- Всі інші повідомлення фізично відсутні в DOM — на їхньому місці порожнеча `<!---->`.
- Angular сам вирішує, які вузли знищити, а які відтворити при скролі.
- Кількість DOM-вузлів завжди фіксована (~15-20 turns), незалежно від того, скільки повідомлень у чаті.

### Де зберігається чат
- Чат зберігається як JSON-файл у прихованій папці **"AI Studio"** на твоєму Google Диску.
- У браузері дані живуть у **закритих Angular-сервісах** (приватні поля класів TypeScript), доступ до яких через `__ngContext__` не дає корисних даних — лише масив HTML-вузлів скролера, а не об'єктів повідомлень.
- Кожне повідомлення має UUID (`turn-XXXXXXXX-...`), який відповідає ID в JSON-файлі на Диску.

### Формат JSON-файлу на Диску
```json
{
  "chunkedPrompt": {
    "chunks": [
      {
        "role": "user",
        "text": "...",
        "tokenCount": 75
      },
      {
        "role": "model",
        "parts": [{"text": "...", "thought": true}, {"text": "..."}],
        "isThought": true,
        "finishReason": "STOP"
      }
    ]
  }
}
```
Поле `isThought: true` або `parts[].thought: true` позначає блоки "Thinking Process" моделі.

### Мережева архітектура (XHR/SSE)
- Запити на генерацію йдуть через `XMLHttpRequest` на `/GenerateContent`.
- Відповідь приходить потоком (Server-Sent Events всередині XHR).
- Коли AI Studio вирішує заблокувати відповідь, воно надсилає спеціальний chunk з `finishReason: 8` (Content Policy) і викликає `xhr.abort()`.
- `modules/bypass-new.js` перехоплює цей момент і:
  1. Замінює `finishReason 8 → 1` (STOP) у відповіді.
  2. Блокує виклик `xhr.abort()`.

## 3. Що НЕМОЖЛИВО зробити — і чому

### ❌ Ctrl+F (пошук по всьому чату)
**Причина:** Virtual scroll. Angular фізично видаляє з DOM всі повідомлення за межами екрану. Браузерний `Ctrl+F` шукає тільки в DOM. Повідомлення на позиції 200 зі 700 не існує в DOM, якщо ти зараз дивишся на повідомлення 700.

**Чому не обійти:**
- Щоб знайти слово у повідомленні №200, треба спочатку проскролити туди, дочекатися, поки Angular його відрендерить, і тільки тоді шукати.
- Це займає хвилини для великих чатів і є нестабільним.

---

### ❌ Миттєвий повний експорт тексту зі сторінки
**Причина:** Та сама. В будь-який момент часу в DOM знаходяться тільки ~15 видимих повідомлень. Решта — пусті `<!---->`.

**Що ми пробували:**
1. `MutationObserver` — перехоплює тільки те, що Angular рендерить при скролі.
2. `__ngContext__` дамп — повертає масив HTML-вузлів (теги, ID), але не текст.
3. Повільний автоскрол — **технічно працює**, але для 700 повідомлень займає ~10-15 хвилин і навантажує браузер.

**Єдине правильне рішення:** скачати JSON безпосередньо з Google Диску → папка "AI Studio".

---

### ❌ Витягти чат-дані з пам'яті Angular
**Причина:** Angular 17 зберігає стан застосунку у приватних полях TypeScript-класів (компілятор закриває їх). `__ngContext__` на DOM-вузлах дає тільки масив посилань на HTML-елементи, але не об'єкти з текстом повідомлень.

**Що ми побачили в реальності:**
```javascript
window.__btsRawMem[1] = {
  id: "turn-2867984E-...",
  rawContext: 260,      // це просто індекс у внутрішньому масиві Angular
  tag: "MS-CHAT-TURN"  // посилання на HTML-вузол, а не дані
}
```
Тут немає ні `role`, ні `text`. Тільки покажчик на DOM.

---

### ❌ Читання/зміна System Instructions програмно
**Причина:** `ms-system-instructions-panel` є Angular-компонентом з власним станом. Читання значення через `querySelector` повертає порожній рядок, бо Angular не зберігає текст у `value` стандартного `<textarea>` — він тримає його у внутрішній моделі компонента.

Запис через `nativeInputValueSetter` + `dispatchEvent('input')` **іноді** спрацьовує, але після перезавантаження чату або SPA-навігації Angular скидає стан з власного кешу, ігноруючи наш запис.

---

### ❌ Стабільний CSS-override без `!important`
**Причина:** Angular додає динамічні атрибути-скоупи до всіх елементів (`_ngcontent-ng-c1765833589`), і їхній CSS має вищу специфічність. Будь-який стиль без `!important` буде мовчки перекритий Angular.

**Важливо:** `!important` ламає деякі анімації Angular Material і може викликати мигання при рендері нових повідомлень.

---

### ❌ Авто-збереження/версіонування чату локально
**Причина:** AI Studio не надає WebSocket або Polling API, за яким можна слухати зміни в чаті. XHR-перехоплення (`modules/bypass-new.js`) ловить тільки нові генерації моделі — але не редагування, видалення або регенерації попередніх повідомлень.

Повністю надійний авто-бекап вимагав би або доступу до Google Drive API (OAuth), або постійного дорогого DOM-скану.
