# Security Policy

## Supported Versions

Studio.lab is a community-driven project. We always recommend using the latest available version from the `main` branch to ensure you have the most up-to-date performance improvements and security patches.

## Reporting a Vulnerability

Use **Security → Report a vulnerability** in [the GitHub repository](https://github.com/dorimommy/Studio.lab/security) if private vulnerability reporting is enabled. If that option is unavailable, open an issue requesting a private contact without including the exploit, user records, session tokens, server secrets or other sensitive material. Ordinary functional bugs can be reported in public issues. Account/backend security issues should be coordinated privately before public disclosure.

## Security Architecture

Studio.lab has a local browser extension and an optional Supabase account backend. It does not load remote extension scripts or collect extension analytics. It contacts GitHub for release discovery and, when accounts are used, contacts the bundled Supabase project and Google's sign-in provider.

* **Credential boundary:** the background service performs OAuth authorization-code login with PKCE and validates the callback origin, path and per-attempt state. Bearer and refresh tokens persist in extension-origin IndexedDB; they are not sent to content scripts, ordinary settings exports, diagnostics or page DOM events. Google provider tokens are discarded.
* **Native settings boundary:** AI Studio's Settings opener launches a unified shell inside the original Material/CDK dialog. The adapter moves the existing `ms-user-settings-dialog` into that shell; it does not clone controls or write Angular/private application state. Theme, submit key, autocomplete, applet notifications and microphone remain native GAIS controls with GAIS persistence. Native labels/descriptions are searched locally, and temporary DOM/ARIA changes are restored on disposal. The original dialog retains the focus trap and unified accessible label.
* **Home profile:** Home reads the name/avatar already displayed in GAIS's visible Google Account control. Avatar URLs are restricted to HTTPS `googleusercontent.com` hosts. This display does not read or expose the private Studio.lab/Supabase identity stored inside Account. GAIS preferences and profile display are excluded from `slState` and cloud synchronization.
* **Account commands:** Settings embeds `account/account.html` and `account/catalog.html` at the extension origin, with their packaged CSP and no iframe sandbox attribute. Operations require an exact packaged URL (catalog permits only its empty, `#library`, `#market` or `#profile` fragment), the extension origin/runtime ID, and, for an embedded child frame, an HTTPS AI Studio parent tab. Account permits ordinary account operations, own-profile editing, membership and server-authorized owner controls; other catalog/social commands require Market. Host content scripts cannot invoke these account/catalog commands or read their private frame DOM. The private account/catalog HTML entry points, independent theme-preview HTML entry point and public extension assets are web-accessible to HTTPS AI Studio; private scripts and styles remain internal resources. The trusted source/origin-checked UI bridge carries navigation/focus signals, bounded numeric geometry/theme/device enums and a read-only Market search query limited to 100 characters. The explicit preview exception carries only a validated theme palette, opacity and a bounded request ID. It carries no stored identity, preference records, prompt contents, document metadata, account commands or credentials. Focus restoration asks the exact original private frame to focus its own remembered editor control; the host receives no control IDs or values.
* **Connection boundary:** validated public configuration is fixed by the bundled `account/config.js`; stored values and runtime messages cannot change it. The manifest grants the exact bundled HTTPS project host, and CSP connections are restricted to that host and the GitHub API. Sign-in has no extra host-permission request. Account fetches reject remote redirects. A build that changes the project clears previous-project private session and sync state while retaining ordinary local preferences.
* **Data minimization:** preference schema 1 permits module switches, cleaner switches, optimization mode and an integer turn limit. Chats, drafts, instructions, profile content and API credentials are excluded from preference backup. The separate catalog stores themes and system instructions only through explicit save/publish actions; it never imports existing chats, drafts or native instruction libraries into the cloud automatically. Google/Supabase still process identity, authentication and infrastructure logs; this is separate from extension analytics.
* **Catalog boundary:** themes contain 13 allowlisted HEX colors, one permanently transparent border token and six bounded numeric opacity values with contrast checks against composited surfaces. Legacy version-one palettes remain importable. Themes never contain custom CSS, scripts or remote resources. The packaged module uses existing GAIS/MWC tokens only while Modern Web Chat is enabled; Account, Market and native Settings retain neutral colors and unchanged CSP. Explicit preview sends only the validated palette/mode and a bounded request ID across the exact-frame bridge. It opens an isolated packaged component document using the production Modern Web Chat stylesheet and control renderers with sanitized native GAIS markup and a fixed public sample. The document has no account registry, storage listeners or native chat/model API hooks, and accepts palette updates only from its allowlisted parent origin, exact parent window and matching request ID. Preview sends no model request, reads or opens no user chat, and writes no palette or toggle to storage. The live workspace route, chat and colors remain untouched. Return restores the connected editor. Host preview acknowledgements cannot persistently apply an item; **Use theme** stays in the private detail page, and enabling Modern Web Chat requires its explicit use action. Prompts are bounded plain text and never evaluated as HTML or JavaScript. Only explicitly published documents can be fetched through anonymous market RPCs; owner IDs and account emails are omitted from every catalog record. Creation/editing requires a Google-authenticated JWT and derives ownership from `auth.uid()`. Owner RLS, revoked direct table/private-helper grants, independent quotas, per-document revisions and server-generated IDs protect cloud writes. Deleting an existing document cannot be undone by a stale update. Local installed copies are independent of publications and preference backup.
* **Public profiles and social state:** verified Studio.lab Google sign-in automatically assigns a random safe nickname and unique tag, editable in Account. An idempotent owner-only RPC also initializes older accounts lacking a profile and preserves existing edits. Google name, email and avatar are never copied into the public profile. A random public profile ID differs from the Auth ID. Public reads expose only public profile fields, counts and published item metadata. Follow/like/bookmark writes set an absolute desired state, derive the actor from the verified Google JWT and require the UI's captured account ID before the worker calls the server. Saved references are private and never install or apply an item. RLS, revoked direct grants, serialized per-user quotas and profile revisions protect writes. Account deletion cascades owned profiles, reactions and follows, including follows targeting the deleted profile.
* **Server authorization:** every settings RPC derives `user_id` from `auth.uid()`. Only authenticated callers can execute the RPCs. RLS is enabled; direct table grants are revoked from API roles. Private validation/quota helpers have no API execution grants and use an unexposed schema. Definer functions have empty search paths and qualified relation names.
* **Market roles and moderation:** public badges derive from private roles and paid entitlement periods. A SQL-operator-only bootstrap binds the single owner to an existing confirmed Google Auth UUID using the operator's exact email, never a mutable public tag. Only that owner can grant staff, review moderator applications or restore moderated publications. Approved applications cannot regress to pending; moderator grants require approval. Removal records an audit and a payload-free snapshot of public metadata, removes every public read surface and prevents author republishing until restoration. The owner queue shows that public snapshot without exposing subsequent private edits. Role changes cannot grant a paid blue check. These migrations require separate backend deployment; local UI changes do not activate roles.
* **Write consistency:** compare-and-swap revisions prevent silent stale writes. Deletion preserves a monotonic tombstone until account removal, preventing an offline device from recreating deleted preferences without an explicit current-revision choice. Each user's RPC traffic shares a persisted 60-calls-per-minute quota.
* **Account deletion:** the Edge Function verifies the bearer with Auth, requires explicit confirmation and recent OAuth authentication, checks active session ownership, and deletes only the caller. An enrolled verified Supabase MFA factor requires AAL2. Administrative keys exist only in the server runtime. Auth deletion cascades Studio.lab cloud preferences, private library documents, publications, public profile, social records and their quotas. Other users' installed/downloaded copies cannot be recalled.


## Threat Boundaries and Deployment

The public project URL and publishable key are visible by design. They are not secrets and do not replace authorization. Project administrators and a compromised server secret can access cloud preferences; the preference document is not end-to-end encrypted. Session storage is isolated from the host page, not protected against a compromised device/browser profile or extension-origin code. An attacker holding a valid user token can act as that user until the token is rejected or expires. Supabase session revocation does not instantly expire every already-issued access JWT; choose appropriate token lifetimes and refresh/revocation policies.

The per-user RPC quota does not replace project-wide traffic, signup or Auth abuse controls. Require administrator MFA, restrict project membership, keep server keys out of clients, configure Auth rate limits and alerts, review backups, and run the database Security Advisor. Keep `studio_lab_private` outside exposed API schemas and do not grant direct access to the settings/quota tables. Backend deployment and administration are maintained separately from the extension package.

Google AI Studio and the user's Google account remain separate security boundaries. Studio.lab's account login requests basic Google identity; it does not request Gmail, Drive, AI Studio or Google API-key access. Local feature code can interact with AI Studio through its existing integration, so new scripts, host-page bridges and dependency changes still need security review.
